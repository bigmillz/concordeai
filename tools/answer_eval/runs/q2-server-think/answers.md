## q30 — Quantization explained

**Q:** Explain what 4-bit quantization does to an LLM and when it actually matters. Keep it short and technical.

*75.27s, 938 chars, models: Ollama1 · gpt-oss:20b, Ollama1 · ministral-3:14b, Ollama1 · gemma4:12b, searched: False, drafts: Ollama1 · gpt-oss:20b, Ollama1 · gemma4:12b, Ollama1 · ministral-3:14b (review)*

4‑bit quantization replaces each 32-bit floating-point weight in an LLM with a 4-bit integer, shrinking the model size by roughly **8×** and cutting GPU memory *traffic*.
The trade-off is a loss of numerical precision: the finer gradations of weight values are rounded, which **typically reduces perplexity by a few percent** and can hurt downstream tasks that rely on subtle probability differences.

It matters most when you must run a large model on constrained hardware—edge devices, inference‑only GPUs with less than 8 GB VRAM, or when you need to serve many concurrent requests with tight latency budgets. In those scenarios the memory‑bandwidth savings outweigh the modest accuracy dip.

For fine‑tuning, training from scratch, or highly sensitive applications (e.g., medical diagnostics), 4‑bit quantization is usually avoided or used only with careful per‑layer calibration and post‑training adjustments to keep errors in check.
