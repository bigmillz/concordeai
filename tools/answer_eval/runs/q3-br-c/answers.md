## q30 — Quantization explained

**Q:** Explain what 4-bit quantization does to an LLM and when it actually matters. Keep it short and technical.

*26.59s, 1952 chars, models: Gemma 4 26B, searched: False, drafts: *

4-bit quantization compresses the model's weights from high-precision formats like **FP16** or **BF16** to a 4-bit integer representation to drastically reduce the memory footprint.

In a high-precision model, weights are stored as floating-point numbers with wide dynamic ranges. Quantization maps these values into one of **16 discrete levels** (2^4). Because 16 levels cannot represent the original distribution of weights, the process uses a **scaling factor**—a multiplier applied to the quantized values to map them back to the approximate original range during inference.

The primary driver is **VRAM capacity**. A 70B parameter model in FP16 (16-bit) requires ~140GB of VRAM, which exceeds most single-GPU setups. In 4-bit, that same model requires ~40GB, allowing it to run on a single **A6000** or two consumer **RTX 3090/4090** cards.

**Perplexity** measures the loss in model "intelligence" or predictive accuracy caused by quantization noise. Modern techniques like **GPTQ**, **GGUF**, or **AWQ** minimize this error by using group-wise scaling or calibration datasets to ensure the most important weight ranges are preserved.

It matters in these specific scenarios:

*   **Hardware constraints:** 4-bit is often the **best option** for local execution because it enables much larger, more capable models to fit on consumer-grade hardware.
*   **Inference speed:** Moving 4-bit weights from VRAM to the GPU cores requires less bandwidth than 16-bit weights, often resulting in higher **tokens per second**.
*   **Deployment economics:** In production, 4-bit quantization significantly lowers the cost-per-query by allowing higher-density packing on existing hardware.

Going below 4-bit (to 2-bit or 3-bit) typically hits a "quantization cliff" where the model's reasoning capabilities collapse. For most use cases, **4-bit to 6-bit** is the optimal sweet spot where you maximize memory savings while maintaining near-original accuracy.
