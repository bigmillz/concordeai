## q30 — Quantization explained

**Q:** Explain what 4-bit quantization does to an LLM and when it actually matters. Keep it short and technical.

*25.48s, 1884 chars, models: Gemma 4 26B, searched: False, drafts: *

4-bit quantization maps high-precision weights (typically **FP16** or **BF16**) to a discrete set of 16 possible values to compress the model's memory footprint.

Because 4 bits cannot represent the nuance of much larger floating-point ranges, this process introduces **quantization error** (noise). To mitigate this, modern techniques like **GPTQ** (Post-Training Quantization) or **AWQ** (Activation-aware Weight Quantization) use calibration datasets to identify and protect the most critical weights, minimizing the impact on the model's **perplexity** (the measure of how well the model predicts the next token).

## When it matters

The decision to use 4-bit quantization is driven by the trade-off between hardware constraints and the scale of the model architecture.

**Memory-constrained environments** — This is the primary driver. A **70B** parameter model in FP16 requires ~140GB of VRAM, which exceeds most single-GPU setups. In 4-bit, that same model fits into **~40GB**, allowing it to run on a single **RTX 6000 Ada** or dual **RTX 4090s** (~48GB total). If you need to fit a large model on consumer-grade hardware, 4-bit is the standard.

**Model scale vs. intelligence loss** — The impact of quantization is inversely proportional to model size. If you quantize a tiny model (e.g., **3B** parameters) to 4-bit, the intelligence loss is often massive because the model lacks the capacity to absorb the noise. If you quantize a massive model (e.g., **405B**), the degradation is often negligible because the sheer parameter redundancy allows the model to remain highly capable despite the loss of precision.

**The Verdict**
Use 4-bit when you need to trade a small percentage of accuracy for a massive reduction in VRAM footprint. If you have the headroom to run the model in **8-bit** or **FP16**, do so, as the perplexity will always be better at higher bit depths.
