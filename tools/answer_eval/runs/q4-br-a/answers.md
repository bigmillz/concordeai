## q30 — Quantization explained

**Q:** Explain what 4-bit quantization does to an LLM and when it actually matters. Keep it short and technical.

*33.73s, 2315 chars, models: Gemma 4 26B, searched: False, drafts: *

Quantization reduces the precision of model weights from high-bit formats like **FP16** or **BF16** to lower-bit representations to shrink the memory footprint and increase throughput.

In a 16-bit model, each parameter occupies 2 bytes of VRAM. Moving to **4-bit quantization** reduces that footprint to roughly **0.5 bytes per parameter**, allowing you to fit much larger models into much smaller memory pools.

## The Mechanism
The process maps a wide range of continuous floating-point values to a narrow set of discrete levels (16 possible values in 4-bit). This creates **quantization error**, where the rounding between the original weight and the new value causes a loss in mathematical precision.

Modern algorithms like **GPTQ** (Post-Training Quantization) or **AWQ** (Activation-aware Weight Quantization) mitigate this by using calibration datasets to protect "salient" weights. They ensure that the weights most responsible for the model's output stability are preserved with higher fidelity, while less impactful weights absorb the bulk of the rounding error.

## When it matters
The decision involves a trade-off between **VRAM capacity** and **perplexity** (the measure of how much the model's predictive accuracy degrades).

*   **Hardware constraints:** This is the primary driver. A **70B parameter** model in FP16 requires roughly **140GB of VRAM**; it is impossible to run on a single consumer GPU. At 4-bit, that same model fits into roughly **40GB**, making it runnable on two consumer cards or a single professional-grade GPU.
*   **Inference speed:** Because LLM inference is typically **memory-bandwidth bound**, moving smaller 4-bit weights from VRAM to the compute cores is faster than moving 16-bit weights. This often results in a significant increase in **tokens per second**.
*   **Model scale vs. Quality:** The "intelligence" loss from 4-bit quantization is much more noticeable in small models (e.g., **1B–8B** parameters) because every weight represents a larger percentage of the total logic. For models **30B and larger**, the loss is often negligible for most practical tasks.

**The verdict:** Use 4-bit to fit a larger, more capable model onto hardware that would otherwise be too small. If you have the VRAM to spare, 8-bit or FP16 is the better path to maximize accuracy.
