## q30 — Quantization explained

**Q:** Explain what 4-bit quantization does to an LLM and when it actually matters. Keep it short and technical.

*30.22s, 2645 chars, models: Gemma 4 26B, searched: False, drafts: *

4-bit quantization maps the model's weights from high-precision formats like **FP16** or **BF16** to a 4-bit integer-based representation to drastically reduce memory footprint and increase throughput.

In a standard transformer, weights are typically stored as 16-bit floating-point numbers. Moving to 4-bit involves mapping those wide-range values into a much narrower scale using a **scale factor** and a **zero-point** (or group-wise quantization) to fit the original distribution into the 16 possible values available in 4 bits.

The primary cost is **perplexity degradation**—the loss of mathematical nuance in the model's probability distributions. Forcing complex decimal values into a coarse 4-bit grid can slightly degrade the model's ability to predict the next token with high precision.

**The trade-off: Perplexity vs. Throughput**

The benefits often outweigh the accuracy loss for several reasons:

*   **VRAM capacity**: A 70B parameter model in FP16 requires **~140GB** of VRAM. At 4-bit, that same model fits into **~40GB**, allowing it to run on consumer-grade hardware like a Mac Studio or dual RTX 3090/4090 setups.
*   **Memory Bandwidth**: LLM inference is frequently memory-bandwidth bound. Moving 4-bit weights from VRAM to the GPU cores is significantly faster than moving 16-bit weights, resulting in a massive increase in **tokens per second**.
*   **Cache hits**: Smaller weights increase the likelihood of model parameters residing in higher-speed cache levels, reducing latency.

**When it actually matters**

**When it doesn't matter:**
If you are running a small model (e.g., **8B parameters** or smaller) for simple tasks like summarization, the 4-bit quantization loss is often negligible compared to the hardware savings.

**When it matters:**
*   **Large-scale models**: For massive models (e.g., **Llama-3 70B**), 4-bit is the "sweet spot." The parameter scale provides enough redundancy that the model can tolerate the quantization error without losing significant reasoning capabilities.
*   **Edge deployment**: For mobile devices or local workstations with limited VRAM, 4-bit is often the only way to make inference possible.
*   **Strict latency requirements**: If you need real-time streaming, the throughput gains of 4-bit are essential to minimize "time to first token" and sustain high generation speeds.

For almost all local deployment and production inference, 4-bit is the industry standard. Unless you are performing highly sensitive scientific modeling or active fine-tuning where decimal precision is the primary requirement, 4-bit is the most efficient path for RAG and agentic workflows.
