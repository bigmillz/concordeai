## q30 — Quantization explained

**Q:** Explain what 4-bit quantization does to an LLM and when it actually matters. Keep it short and technical.

4‑bit quantization compresses every weight from a 32‑bit float to a 4‑bit integer, shrinking the weight tensor by **≈8×** (activations, if also quantized, can add extra savings). The process stores a per‑block scale and zero‑point, so during inference the integer is rescaled back to a float‑like range. Because the precision is low, you lose a few percent in perplexity/BLEU, but for most downstream tasks the drop stays under **2 %**. Training with 4‑bit weights is rarely practical, and the added error can be unacceptable for high‑precision or safety‑critical work. The real advantage shows up when you need to fit a model into limited GPU memory or run many copies of it concurrently—common in edge deployments or multi‑tenant inference. A 30‑B model still exceeds an 8‑GB GPU even after 4‑bit quantization, but smaller models (e.g., 6‑B or 13‑B) can fit comfortably.
